SCREEN 1 Home — populated · empty · RTL Arabic
Decisions I made from design.md
· Blue budget spent exactly three times per screen — active lens segment, progress bars, active Home tab. Empty state: lens, Discover button, Home tab. Nothing else is blue.
· Lens chips are one segmented group in a 48 dp row (chips are 36 dp, so the shape stays right and the touch target still clears 48).
· Continue cards are 112 × 168 (2:3, r12): the caption line (Ch. 254 · 2h ago) has to fit on one line un-truncated in both locales, and 104 dp lost the timestamp. At 112 the third card still peeks 17 dp, so the rail still reads as scrollable.
· See all lives in the Latest updates header rather than as a sixth row, so no row-shaped thing is a button.
· Stat chips are a 2 × 2 grid, not a row of four: at 84 dp wide the 13 dp label “In progress” wraps, and I will not shrink a size that is not in the scale.
Assumptions · and three things to confirm
· Covers and 48 dp thumbs are placeholders. Real art is the one thing this screen still needs.
· The wordmark is your supplied PNG, uncropped in proportion and unrecoloured — the only rasterised element (brush lettering cannot be typed). Everything else is live text.
· Rows 3–5 of Latest updates fall below the fold. The artboard is the true first viewport at 852 dp; all five rows are in the markup with exact values.
Ask once: (1) Arabic strings not in design.md — rail captions use the compact relative form (ساعتان · يوم · 3 أيام) because قبل + unit does not fit 112 dp; list rows keep the long form (قبل دقيقتين). Also عرض الكل for See all. Caption line-height is 20 dp in both locales — Arabic needs it and one value beats two. (2) NEW pill label colour on Accent — I used Ink Black #08080C for contrast; white on #06B6D4 fails. (3) Type-chip label — 11 Medium; the scale has nothing below 12.
