SCREEN 9 Downloads — storage line · Active · Queued · Failed
Decisions
· The storage line is one row, not a card: 1.2 GB in downloads with Clean up as an outlined pill at the trailing edge. A donut chart of your own storage is decoration; the number and the verb are the whole content.
· Blue is spent on the one active download and nowhere else. Queued rows carry a Muted position number (2, 3, 4) instead of a 0%-blue bar — a queue of blue tracks reads as four things happening when one is.
· Failed uses Error #EF4444 for the reason line and an outlined Retry. The reason is written out — Source returned 403 — because "Failed" alone sends people to the queue to guess.
· Section headers carry counts, and Active carries the global control: one Pause all in the top bar, not a pause button per row plus a global one. Per-row pause lives on the active row only, where pausing means something.
· Rows are 72 dp with a 48 dp thumb (r12) — the update-row component, reused, plus a 3 dp progress bar flush at the thumb's bottom edge on the active one. Neutral seam words throughout: items, never chapters-and-episodes in the same breath.
Notes for you
· Blue count — 14a two (active progress bar, Downloads tab). 14b two (Long-press hint's button, Downloads tab).
· The footer row See downloaded items goes to Library with the Downloaded filter already on — the one place this screen hands off rather than acting.
· Queue reordering is drag (the 6-dot handle) and removal is swipe; both are gesture affordances, so the handle is the only thing drawn. Nothing on this screen is a hover state.
· 14b empty state says Nothing downloading and teaches the batch gesture in the sentence, with Go to Library as the verb — an empty queue with no way forward would break the never-empty rule.
One value not in design.md: the 20 dp queue-position numeral (13 Regular tabular in a 24 dp box). Confirm and I will add it.
