SCREEN 10 Search — one field, library first, then sources
Decisions
· In your library comes first, always — even when it has one hit and the sources have twelve. The most common search is "where is that thing I already have"; making the shelf win the top of the screen answers it without a filter.
· Library results are rows, source results are a grid. Different shapes because they are different acts: a row is retrieval (title, where you are in it, one tap to resume), a card is appraisal (cover, source, is this the one). Same-shaped results would need a header to tell them apart.
· Each source answers separately and asynchronously. MangaDex has returned 8, Comick 3, Jellyfin is still going — so its group shows three skeleton cards rather than a spinner over everything. One slow source must never hold the fast ones hostage.
· The lens button sits in the field's trailing edge, not the top bar — here the field is the top bar. Under a filtered lens the source groups of the other medium disappear entirely, which is the visible answer to “I can't search to add an anime”.
· 13c is the honest failure: nothing found and no anime sources installed. It names the cause in words and offers Add sources — never a shrug.
Notes for you
· Blue count — 13a two (the one library row's progress bar, Search tab is not a tab so the bottom bar keeps the caller's tab: Discover here). 13b two. 13c two (Add sources, caller's tab).
· 13b is the empty-query state: recent searches as plain rows with a clear glyph, then Trending searches from the same metadata feed Discover uses — so the screen is never blank, per the never-empty rule.
· Source group headers carry the source name and the count, and the type chip, because a source is single-medium and that is the fastest place to see which half you are looking at.
One value not in design.md: the source-result card at 104 × 156 with a 2-line title below (the Library grid is 112 wide; a 3-up grid inside a group with its own 16 dp padding lands at 104). Confirm and I will write it in.
